## Case: Litware Media {#litware}
#### Overview
Litware Media is a digital publishing company headquartered in Amsterdam. Litware operates a news website, a short-form video channel, and a podcast network. Litware builds, deploys, and manages its generative AI and agent-based solutions by using Microsoft Foundry.

Litware uses Microsoft Entra ID for identity management, authentication, and authorization. The editorial staff belong to a team named Newsroom Team. A separate team named Trust and Safety Team reviews advertiser-submitted images before the images are published.

#### Existing environment
##### Microsoft Foundry
- **Foundry1:** A Microsoft Foundry resource deployed to the West Europe region. Foundry1 contains two projects named Project1 and Project2. Foundry Tools, including Azure Vision, Azure Content Safety, and Azure Content Understanding, are used through Foundry1.
- **Project1:** Used by the Newsroom Team. Project1 contains two Foundry Models deployments: a gpt-4.1 deployment named gpt-4.1 and a text-embedding-3-large deployment. Project1 contains a project connection named search1-conn that connects to search1 by using the managed identity of Project1 (Microsoft Entra ID authentication).
- **Agent1:** A Foundry Agent Service agent in Project1 that is intended to help editors find archived content. Agent1 does NOT have any knowledge tools and answers only from the general knowledge of its base model.
- **Project2:** Used by the Trust and Safety Team and by the design team. Project2 contains a gpt-image-1 deployment that the design team uses to generate sponsored artwork.

##### Azure resources
- **storage1:** An Azure Blob Storage account that contains the following containers: articles (PDF article layouts that contain embedded charts and tables that span multiple pages), photos (JPEG photos, approximately two million, with several thousand uploaded daily), clips (MP4 news clips between 30 seconds and five minutes long that contain narration), podcasts (MP3 episodes up to 90 minutes long), and voicemail (WAV recordings of listener voicemails, each less than 10 MB).
- **search1:** An Azure AI Search service on the Standard tier. search1 contains an index named archive-index. An indexer named indexer1 populates archive-index from the articles container by using a skillset named skillset1. archive-index contains searchable text fields and a vector field and has a semantic configuration. Public network access to search1 is disabled. Diagnostic settings are NOT configured for search1.
- **cms1:** The Litware content management system (CMS), a Python web app hosted on Azure App Service. Editors use cms1 to publish articles, photos, clips, and podcasts. cms1 has a system-assigned managed identity.

#### Planned changes
Litware plans to implement the following changes:

- Add a feature named Describe Photo to cms1 that generates alt text for every photo published on the website.
- Add a feature named Photo Desk to cms1 that lets an editor ask questions about a set of photos taken at a single event.
- Add the content of the clips container to archive-index, and let editors find photos that resemble a photo they upload.
- Connect Agent1 to archive-index.
- Automate the review of advertiser-submitted images.
- Add a feature named Listener Line to cms1 that answers questions about listener voicemails.
- Implement monitoring for search1.

#### Business requirements
Litware identifies the following business requirements:

- Editors must be able to find archived content by asking Agent1 natural language questions, and the responses of Agent1 must include citations to the indexed sources.
- Every photo published on the website must have alt text so that screen readers can describe the photo to blind and low-vision readers.
- Advertiser-submitted images must be reviewed automatically before publication. The list of prohibited symbols changes weekly.
- Readers must be able to verify that sponsored artwork generated by Litware is AI-generated.

#### Technical requirements
Litware identifies the following technical requirements:

- The alt text generated by Describe Photo must be a single sentence in English that describes the whole photo, must NOT contain gender terms such as man or woman, and must be produced by a single Foundry Tools API call that does NOT require a model deployment.
- Photo Desk must accept up to eight photos from one event in a single request together with a question. The answer must be based only on what is visible in the photos, and small details such as jersey numbers and signage text must be read accurately. cms1 must call the model through the Project1 endpoint by using its managed identity.
- Each clip must be split into segments. Each segment must have a natural-language description that combines the visual content and the speech, and a WebVTT transcript. The output must be usable by archive-index without custom post-processing.
- For the articles, tables that span multiple pages must be extracted as a single unit, and the embedded charts must receive AI-generated descriptions that are inlined into the Markdown chunks that are indexed.
- Editors must be able to search the photos by using a photo as the query.
- Agent1 must query archive-index by using search1-conn, must run a hybrid (vector and keyword) query with semantic ranking, and must NOT require custom retrieval code.
- Listener Line must answer a text question about what a caller said and about the tone of the caller in a single chat completions request that receives the WAV file directly, without a separate speech-to-text step.
- The Newsroom Team must be able to identify which PDF files indexer1 did not index, and the reason, even when the status of the indexer run is Success.
- The Newsroom Team must be alerted when skill executions in skillset1 fail, and the alert must identify the skill by name.
- The Newsroom Team must be alerted when the average query response time of search1 exceeds two seconds.

#### Security and compliance requirements
Litware identifies the following security and compliance requirements:

- API keys must NOT be used to access search1 or the Foundry Models deployments.
- cms1 must authenticate to Foundry1 by using its managed identity.
- An advertiser-submitted image that contains any symbol on the prohibited-symbol list must be rejected. The list consists of sample images, not text. Updates to the list must take effect within hours and must NOT require training a model.
- Advertiser-submitted images must also be checked for sexual, violent, hateful, and self-harm content in the same review.
- Sponsored artwork generated by the gpt-image-1 deployment must carry tamper-evident provenance information that a reader can verify.

#### Issues
Litware identifies the following issues:

- The most recent run of indexer1 has a status of Success, but several PDF files uploaded to the articles container last week are never returned by queries against archive-index.
- A prototype of Describe Photo produced alt text that described an adult woman as a girl.
- An advertiser-submitted image that contained a prohibited symbol was published last month because the review was performed manually.
- Agent1 cannot answer questions about the archived content.
