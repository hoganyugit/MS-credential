### S1 type=single kp="Security, authentication & governance" sk=A1.7,A1.2
A company plans to publish a customer service agent built in Copilot Studio to its public website. Customers do not have accounts in the company's Microsoft Entra tenant; they sign in to the company's portal by using a consumer identity provider that complies with the OAuth 2.0 standard.

The agent must meet the following requirements:

- Customers must be able to ask general questions about shipping policies without signing in.
- A topic that returns a customer's order history must call the order API on behalf of the signed-in customer by using the customer's access token.
- The agent must keep working on the custom website channel.

You need to configure authentication for the agent.

What should you do?

- A. Select Authenticate with Microsoft and turn on Require users to sign in.
- *B. Select Authenticate manually with the Generic OAuth 2 service provider, turn off Require users to sign in, and add an Authenticate node to the order history topic.
- C. Select No authentication and pass the customer's identity to the agent as a global variable that the website sets.
- D. Select Authenticate manually with the Generic OAuth 2 service provider and turn on Require users to sign in.

> why: Authenticate manually 是唯一既支持 Teams 以外渠道、又提供 User.AccessToken 的选项；关闭 Require users to sign in 后，agent 只在遇到需要认证的主题（Authenticate 节点）时才要求登录，一般问题可匿名回答。A 错：Authenticate with Microsoft 只支持 Teams + Microsoft 365 渠道，其他渠道会被阻止，且不提供 User.AccessToken。C 错：No authentication 下 agent 只能访问公开信息，无法代表用户调用 API。D 错：打开 Require users to sign in 会在对话一开始就强制所有人登录，违背匿名提问的需求。
> ref: https://learn.microsoft.com/en-us/microsoft-copilot-studio/configuration-end-user-authentication
> ref: https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-end-user-authentication

### S3 type=single kp="Topics & conversation design" sk=A3.2
A company runs a voice-enabled agent built in Copilot Studio that is connected to Dynamics 365 Contact Center through the Telephony channel. The same agent is also published to the company website. A Message node reads a 10-digit case number to the caller.

Callers report that the case number is spoken too quickly to write down. The company has the following requirements:

- The text shown in the website chat must not change.
- On the phone, the agent must pause between groups of digits and speak the number more slowly.
- The change must be limited to the Message node.

What should you do?

- A. Add two message variations that insert spaces between the groups of digits.
- *B. Add a speech override to the Message node and wrap the case number in SSML break and prosody tags in the spoken message.
- C. Turn on Allow barge-in in the Message node properties.
- D. Increase the Utterance end timeout in the agent's Voice settings.

> why: Speech override 让同一个 Message 节点在语音渠道上念出与文本显示不同的内容，SSML 的 break 标签插入停顿、prosody 标签调整语速，网页上的文本不受影响。A 错：message variation 只是每次随机挑一条文本来发送，既不能控制语速和停顿，还会改变网页显示。C 错：barge-in 只是允许用户打断 agent 播报。D 错：Utterance end timeout 是判断用户是否说完话的等待时间，与 agent 的播报方式无关。
> ref: https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-send-message
> ref: https://learn.microsoft.com/en-us/microsoft-copilot-studio/voice-configuration

The company has the following requirements:

- The card must show the answer text that the node generated for the current question.
- The topic must not send the answer twice.

The topic must then show an interactive Adaptive Card that greets the customer by name, states the number of open orders, and asks the customer to confirm the shipping address in an input field with a Submit button.

The card was designed in the Adaptive Card designer and currently contains hard-coded text.

You need to make the card show the values from the topic variables.

What should you do?

### S6 type=multi kp="Topics & conversation design" sk=A3.8
A company builds an order agent in Copilot Studio. A topic shows two interactive Adaptive Cards in sequence: the first collects a delivery date and a delivery note, and the second asks the customer to confirm the order summary. The agent is published to Microsoft Teams and to the company website.

During testing, the team observes the following:

- When a user selects Submit on the first card after the second card appears, the topic processes the wrong submission.
- The values entered on the first card are not available as variables later in the topic.

You need to resolve the issues.

Which two actions should you perform? Each correct answer presents part of the solution.

NOTE: Each correct selection is worth one point.

- *A. Build each card with an Ask with Adaptive Card node so that Copilot Studio creates output variables from the card's input fields.
- *B. Add a unique identifier to the data payload of each card's Action.Submit and check that identifier in a Condition node before processing the submission.
- C. Add both cards to Message nodes and read the submitted values from System.Activity.Text.
- D. Set How many reprompts to Don't repeat on both card nodes.
- E. Change the cards' schema version to 1.6 and replace Action.Submit with Action.Execute.
