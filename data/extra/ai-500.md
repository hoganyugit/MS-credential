### S2 type=single kp="Orchestration patterns & workflows" sk=A1.2,B4.2
You are designing a Microsoft Foundry multi-agent workflow that resolves billing disputes. A drafting agent writes a resolution, and a reviewer agent checks the draft against a policy checklist. If the draft fails the checklist, the reviewer agent returns it to the drafting agent for revision. An approved resolution can include a refund that a refund tool issues.

You need to design the control loop and the human-in-the-loop controls. The solution must meet the following requirements:

- The review loop must always terminate, even if the reviewer agent never approves the draft.
- If a draft still fails after three review cycles, a human specialist must take over the dispute.
- Refunds of more than $1,000 must never be issued without the approval of a supervisor, even if an agent is manipulated by injected content.

What should you include in the design?

- A. Repeat the loop until the response of the reviewer agent contains the text APPROVED, and add an instruction to the system message of the drafting agent to ask a supervisor before it requests a refund of more than $1,000.
- *B. Enforce a maximum of three review iterations in the orchestration logic and hand the dispute to a human specialist when the limit is reached, and add an approval step to the workflow that pauses before the refund tool is called for amounts of more than $1,000.
- C. Run the drafting agent and the reviewer agent concurrently and accept the draft that most runs approve, and allow the reviewer agent to approve refunds of more than $1,000.
- D. Stop the loop when the cumulative token usage reaches a budget, and configure the reviewer agent to call the refund tool only after it decides that the refund is justified.

> why: 学习路径"Examine production agentic loop architecture"单元指出生产级代理循环必须有显式终止条件：最大迭代上限要"Always include a maximum to prevent runaway loops"，而语义完成检测依赖模型可靠地发出完成信号，单独使用可能永不结束；达到上限后转交人工处理即可保证终止。安全模式文档"Secure autonomous agentic AI systems"要求 deterministic human-in-the-loop：对高风险或不可逆操作的人工审批"through orchestrator logic rather than model reasoning"，所以退款审批必须由工作流在调用退款工具之前强制执行。A 的终止条件和审批都交给模型（文本信号加系统提示），可被注入内容绕过；C 并发投票破坏了起草→审阅的依赖关系，并让 agent 自行批准高额退款；D 的 token 预算只是资源型停止条件，审批仍取决于 agent 的判断，不是确定性控制。

### S3 type=single kp="Multi-agent architecture & design" sk=A1.3,A1.6

- Balance lookups must run without interrupting the customer.
- Transfers must run only after the customer confirms them.
- Before an account is closed, the closure must be disclosed to the customer and confirmed.
- The agent must never infer the emotional state of the customer.
- The boundaries must hold even if the instructions of the agent are bypassed by a prompt injection attack.
